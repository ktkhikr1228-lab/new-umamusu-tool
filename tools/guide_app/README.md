# ガイド確認アプリ(guide_app)

トレーナーガイドの抽出結果を、スクショと見比べて確認するWebアプリです。ラズパイで常駐させ、PCやスマホのブラウザから使います。

- Python 3.11以上の標準ライブラリだけで動きます。npm・Prisma・PostgreSQLは使いません
- 確認作業のデータは SQLite ファイル1つ(既定: `/home/katao/uma-guide-data/guide_app/guide.sqlite3`)。コピーすればバックアップになります
- 撮影(F8)とGemini抽出は今の仕組みのまま使います。このアプリは抽出CSVの取り込みから先を担当します

## 起動(ラズパイ)

リポジトリをcloneした場所で実行します。

```bash
python3 tools/guide_app serve
```

ブラウザで `http://uma-pi:8090/` を開きます。新しい抽出CSVは5分おきに自動で取り込まれます(ホームの「今すぐ取り込む」でも可)。

設定を変えたいときは `config.example.toml` を `config.toml` にコピーして編集します(コミットされません)。

## 確認の進め方

1. ホームでイベントと脚質を選ぶ
2. 左のスクショと右の行を見比べる
   - **要注意の行**(マスタにない名前・◎付き・同じ画像に○と◎・両区分に出ている)だけが開いて表示されます。名前はプルダウンの候補か「手入力…」で直し、✓でOK、誤読や重複は✕で却下
   - **マスタと合致した行**は折りたたまれています。開くと区分の変更や除外ができます
3. スクショと見比べて抜けや読み違いがなければ「この画像OK・次へ」(Space)。合致行がまとめてOKになります。要注意の行は自分でOKにするまで公開されません
4. 撮影時に区分を切り替え忘れた画像は、画像番号をShift+クリックで範囲選択して区分をまとめて変更できます

キーボード: `←` `→` 画像 / `↑` `↓` 行 / `Enter` 行をOK / `X` 行を却下 / `Space` この画像OK

## 公開の進め方

1. 「公開」画面を開く。イベントごとに「追加」「区分変更」「公開済み(変更なし)」「未確認(含めない)」の件数が出ます
2. 「依頼する内容を見る」で中身を確かめ、「公開を依頼する」を押す
3. GitHub Actionsが検証とビルドをしてPRを作ります(数分)。「これまでの依頼」の「PRを見る」から確認してマージすると、サイトに反映されます

- 依頼に含めるのは、OKにした行のうち **サイトにない・区分が違うもの** だけです。サイトにある他のスキルは消しません(前回分に追加)
- サイトの内容は GitHub main の `race_data.json` を5分おきに読み込みます。サイトに同じ区分で出ているスキルは、確認画面でも「公開済み」と表示され、見直さなくても済みます
- マスタにない名前や、同じスキルが両方の区分でOKになっている行があると、直すまで公開できません
- 量が多いときは自動で分けて送り、同じイベントのPRにまとまります
- PRを閉じてやり直したいときは、「依頼済みを取り消す」で再度依頼できるようになります
- 依頼には既存の `~/.config/uma-tool/github_token`(Actions起動権限)を使います。マージはこのアプリでは行いません

## コマンド

```bash
python3 tools/guide_app serve [--port 8090]   # 画面を起動
python3 tools/guide_app import [--force]      # 抽出CSVを取り込む(画面を使わない場合)
python3 tools/guide_app status                # イベントごとの件数
```

## 安全のための仕様

- Tailscale内での利用が前提で、ログインはありません。書き込みは画面からの操作(独自ヘッダ付き・同一オリジン)だけを受け付けます
- 取り込み直しても、画面で直したスキル名・区分・状態は上書きしません
- 行は削除せず、却下(rejected)として残します
