# ガイド確認アプリ(guide_app)

トレーナーガイドの抽出結果を、スクショと見比べて確認するWebアプリです。ラズパイで常駐させ、PCやスマホのブラウザから使います。

- Python 3.11以上の標準ライブラリだけで動きます。npm・Prisma・PostgreSQLは使いません
- 確認作業のデータは SQLite ファイル1つ(既定: `/home/katao/uma-guide-data/guide_app/guide.sqlite3`)。コピーすればバックアップになります
- 撮影(F8)は今の仕組みのまま使います。このアプリはスクショの読み取り(複数モデルの多数決)から公開依頼までを担当します
- アップロード画面(8080)で抽出したCSVも、これまでどおり自動で取り込みます

## 起動(ラズパイ)

リポジトリをcloneした場所で実行します。

```bash
python3 tools/guide_app serve
```

ブラウザで `http://uma-pi:8090/` を開きます。新しい抽出CSVは5分おきに自動で取り込まれます(ホームの「今すぐ取り込む」でも可)。

### 常駐させる(再起動後も自動で起動)

```bash
bash tools/guide_app/guide_app.sh install   # 自動起動を登録して、今すぐ起動
```

| やりたいこと | コマンド |
| --- | --- |
| 動いているか確認 | `bash tools/guide_app/guide_app.sh status` |
| 最新版に更新して再起動 | `bash tools/guide_app/guide_app.sh update` |
| 再起動 / 停止 | `bash tools/guide_app/guide_app.sh restart` / `stop` |
| ログを見る | `bash tools/guide_app/guide_app.sh log` |
| 自動起動をやめる | `bash tools/guide_app/guide_app.sh uninstall` |

- 自動起動は既存のアップロード画面と同じく cron の `@reboot` を使います。既存のcronの行には触れず、このアプリの1行だけを追加・削除します(変更前の内容は `tools/guide_app/run/crontab.backup` に保存)
- アプリが落ちても5秒後に自動で立ち上げ直します。ログは `tools/guide_app/run/guide_app.log`

設定を変えたいときは `config.example.toml` を `config.toml` にコピーして編集します(コミットされません)。

## スクショの読み取り(複数モデルの多数決)

ホームの「撮影済み・未抽出」に、撮影フォルダ(`screenshots/inbox/<イベント>/<脚質>/<区分>/`)のうち、まだ読み取っていないイベントが並びます。

1. 「読み取りを開始」を押す。コースは画像から自動で読みます(読めなかったときだけ、競馬場・芝/ダート・距離を選んで押し直します)
2. 画像の枚数と呼び出し回数の見積もりが出るので、確認して開始する(撮影しただけでは始まりません)
3. 進み具合がホームに出ます。終わると、そのまま確認画面で確認できます

- 設定した各モデルに同じ画像を読ませ、結果を突き合わせます。**全モデルが読んだスキル**は折りたたまれ、**一部のモデルだけが読んだスキル**は「3モデル中1モデルだけが読んだ」と要注意に出ます
- ○・◯・〇の表記ゆれは同じスキルとして数えます。マスタにない読み(誤読の疑い)は、同じ画像で他のモデルが読んだよく似たスキルへの1票として数えます
- 一部のモデルが失敗しても止まりません。もう一度「読み取りを開始」を押すと、失敗した分だけやり直します
- 読み取り済みの画像は呼び直しません。画面で直した名前・区分・状態も上書きしません
- 「撮り忘れの可能性」は、区分フォルダで撮っているのに0枚の脚質・区分があるときに出ます
- スキル名と一緒に、画像のコース・選択中の脚質タブ・見出し(超おすすめ/おすすめ)も読みます。フォルダ(撮影時のホットキー設定)と食い違う画像は「撮影時の設定と画像の中身が食い違っています」と表示され、自動確定の対象から外れます
- 「モデルごとの成績」で、モデル別の失敗数・単独で読んだ数(うち却下)・読み落としの数を見られます。モデルの入れ替えの判断に使えます

### 自動確定

`config.toml` に `auto_confirm = true` と書くと、多数決の結果をそのまま採用します。

| 読み取りの結果 | 扱い |
| --- | --- |
| 過半数のモデルが読み、マスタにある | 自動でOK |
| 1モデルだけが読み、マスタにない | 自動で却下 |
| 1モデルだけが読み、マスタにある | 未確認のまま(人が確認) |
| 撮影時の設定と中身が食い違う画像 | その画像は自動確定しない(人が確認) |

人がOK/却下にした行は、読み取りをやり直しても自動では変えません。公開依頼のボタンとPRのマージは、自動確定でも人が行います。

### モデルの設定

`config.example.toml` を `config.toml` にコピーし、`[[readers]]` を2つ以上書きます(3つがおすすめ。1つだけだと多数決になりません)。OpenAI互換のAPIで、画像を読めるモデルなら使えます。APIキーはファイルに置いて `key_file` で指し、リポジトリには入れません。設定を変えたら `bash tools/guide_app/guide_app.sh restart` で反映します。

## 確認の進め方

1. ホームでイベントと脚質を選ぶ
2. 左のスクショと右の行を見比べる
   - **要注意の行**(一部のモデルだけが読んだ・マスタにない名前・両区分に出ている・サイトと区分が違う。1モデルで読んだ場合は◎付きも)だけが開いて表示されます。名前はプルダウンの候補か「手入力…」で直し、✓でOK、誤読や重複は✕で却下
   - **マスタと合致した行**は折りたたまれています。開くと区分の変更や除外ができます
3. スクショと見比べて抜けや読み違いがなければ「この画像OK・次へ」(Space)。合致行がまとめてOKになります。要注意の行は自分でOKにするまで公開されません
4. 撮影時に区分を切り替え忘れた画像は、画像番号をShift+クリックで範囲選択して区分をまとめて変更できます

キーボード: `←` `→` 画像 / `↑` `↓` 行 / `Enter` 行をOK / `X` 行を却下 / `Space` この画像OK

## 公開の進め方

1. 「公開」画面を開く。イベントごとに「追加」「区分変更」「公開済み(変更なし)」「未確認(含めない)」の件数が出ます
2. 「依頼する内容を見る」で中身を確かめ、「公開を依頼する」を押す
3. GitHub Actionsが検証とビルドをしてPRを作ります(数分)。「これまでの依頼」の「PRを見る」から確認してマージすると、サイトに反映されます

- 依頼に含めるのは、OKにした行のうち **サイトにない・区分が違うもの** だけです。サイトにある他のスキルは消しません(前回分に追加)
- サイトの内容は GitHub main の `race_data.json` を5分おきに読み込みます。サイトに同じ区分で出ているスキルは、確認画面でも「公開済み」と表示され、見直さなくても済みます
- スキルマスタも GitHub main の `skill_master.json` を5分おきに読み込みます(公開時の検証と同じもの)。取得できないときは手元のファイルで動きます
- マスタにない名前や、同じスキルが両方の区分でOKになっている行があると、直すまで公開できません
- 量が多いときは自動で分けて送り、同じイベントのPRにまとまります
- PRを閉じてやり直したいときは、「依頼済みを取り消す」で再度依頼できるようになります
- 依頼には既存の `~/.config/uma-tool/github_token`(Actions起動権限)を使います。マージはこのアプリでは行いません

## コマンド

```bash
python3 tools/guide_app serve [--port 8090]   # 画面を起動
python3 tools/guide_app import [--force]      # 抽出CSVを取り込む(画面を使わない場合)
python3 tools/guide_app status                # イベントごとの件数
```

## 安全のための仕様

- Tailscale内での利用が前提で、ログインはありません。書き込みは画面からの操作(独自ヘッダ付き・同一オリジン)だけを受け付けます
- 取り込み直しても、画面で直したスキル名・区分・状態は上書きしません
- 行は削除せず、却下(rejected)として残します
